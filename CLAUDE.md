# CLAUDE.md

Hey Claude — you're maintaining a **MkDocs documentation site** about AI agent production architecture patterns. Here's everything you need to know.

## What This Project Is

A catalog of 59 architecture patterns (across 12 categories) for taking AI agents from prototype to production. The site is built with MkDocs + Material and published to GitHub Pages. The backbone metaphor: **decisions are the spine, patterns are the vocabulary**.

For the big picture — structure, directory layout, deployment — see `PROJECT.md`. For pattern data, `patterns.yml` is the single source of truth.

## Ground Rules

- **`patterns.yml` + `decisions.yml` are the source of truth.** Everything — patterns, forces, dials, tradeoffs, reference architectures, decision rules — lives here. Don't invent new ones or renumber existing ones. When something needs to change, update the YAML first, run `python scripts/generate.py` to regenerate, align `mkdocs.yml`'s `nav` by hand, and mention it in the commit message.
- **`anti-patterns.yml` is also authoritative** for anti-pattern symptoms, root causes, and preventive patterns.
- **Generated artifacts are hands-off.** `catalog.json`, `llms.txt`, `llms-core.txt`, `llms-full.txt`, `GEN:meta` blocks, and the `pattern-index.md` table are all produced by `generate.py`. Don't edit them directly.
- **When in doubt, follow the exemplar:** `docs/patterns/01-execution/01-request-to-job-gateway.md`. Match its structure, granularity, and tone.
- **New pages start from `templates/pattern.md`** (`scaffold.py` handles this automatically).
- **Write in Japanese.** English terms and pattern names can appear alongside.

## Pattern Page Structure

Every pattern page needs these sections **in this order** (same as the exemplar):

1. YAML frontmatter (`title` + `tags` with category name and relevant `F#`)
2. `# #{number} {title}`
3. `!!! abstract "一言"` — one-sentence TL;DR
4. `## 概要` — 2–4 sentences: what it does and where it fits
5. `!!! info "意思決定上の位置づけ"` — **required**: which forces drive it, relevant dials/tradeoffs, link to the decision flow
6. `## 設計` — components and data flow; add a mermaid diagram if it helps
7. `## 解決する課題` — what characteristics/pressures it addresses; what breaks without it
8. `## 向き / 不向き` — **both are required**; a pattern without "when not to use" is marketing, not engineering
9. `## 要素技術` — concrete implementation options
10. `## 調整（程度）` — only if dials apply; skip the whole section otherwise
11. `## 選定（相反）` — only if tradeoffs apply; skip otherwise
12. `## 関連パターン` — at least one, with relative links
13. `## 参考` — optional references

**Writing tip:** Think **characteristic → broken assumption → required structure → when/when not**. Frame each pattern as "a levee against what breaks in production," not a feature pitch.

## Style Guide

- **Length:** ~250–500 words per pattern. Dense, not verbose.
- **Tone:** Practical and tradeoff-aware. Don't over-assert.
- **Formatting:** Headings, bold, and bullets only when they earn their place. Match the exemplar.
- **Mermaid:** ` ```mermaid ` fences. Prefer `flowchart` / `sequenceDiagram`. Keep it to 3–7 nodes. Skip the diagram if it doesn't add clarity.
- **Admonitions:** Material syntax (`!!! note`, `!!! warning`, `!!! abstract`). TL;DR uses `!!! abstract "一言"`.
- **Code blocks:** Always tag the language.
- **Don't delete existing content.** Fill stubs, extend what's there.

## Cross-Reference Conventions

- **Forces:** `` `[F#]` `` (e.g., `[F4]`). Full list in `docs/foundations/forces.md`.
- **Same-category link:** `[#12 Blackboard](12-blackboard.md)`
- **Cross-category link:** `[#44 Dual-LLM Privilege Separation](../09-security/44-dual-llm-privilege-separation.md)`
- **Decision layer link** (from a pattern page): `../../decisions/tuning-dials.md`
- If a link target **doesn't exist yet**, run `scaffold.py` first — `--strict` builds fail on broken links.
- Always use **file paths** (with `.md`), not raw URLs or made-up anchors.

## Before You Commit

Run all three — they must pass cleanly:

```bash
python scripts/generate.py        # Regenerate from source YAML
mkdocs build --strict              # Catch broken links and nav issues
python scripts/generate.py --lint  # Validate pattern page structure
```

`generate.py` is idempotent — running it twice produces no diff. CI runs it too.

Use `scaffold.py --check` to spot missing pages.

## Definition of Done (one pattern)

- [ ] All required headings present in order; both 向き and 不向き exist
- [ ] `!!! info "意思決定上の位置づけ"` block present
- [ ] `関連パターン` has at least one working relative link
- [ ] `調整`/`選定` sections (if applicable) reference `[F#]` and link to the decision layer
- [ ] Frontmatter `tags` include category name + relevant `F#`
- [ ] `patterns.yml` has `related`, `when_to_use`, `when_not`, `element_tech`, `dials`, `tradeoffs`
- [ ] `patterns.yml` has `selection_criteria`, `summary_plain`, `prevents_anti_patterns`
- [ ] `<!-- BEGIN:GEN:meta --><!-- END:GEN:meta -->` marker present
- [ ] `python scripts/generate.py && mkdocs build --strict` passes
- [ ] Page registered in `mkdocs.yml` nav

## Don'ts

- Change pattern numbers or slugs, or create patterns outside `patterns.yml`
- Edit or commit anything in `site/`
- Copy long passages from external sources (summarize; cite under 参考)
- State uncertain product specs, versions, or pricing as fact
- Bundle multiple patterns in one commit (one pattern = one commit)

## Typical Workflow

1. `python scripts/scaffold.py` — make sure the stub exists
2. Write the `.md` following the template and exemplar; pull `tagline` and `forces` from `patterns.yml`
3. Fill in `related`, `when_to_use`, `when_not`, `element_tech`, `dials`, `tradeoffs` in `patterns.yml`
4. Wire up relative links (generate target stubs first if needed)
5. `python scripts/generate.py` — inject meta blocks, update artifacts
6. `mkdocs build --strict` — fix anything that breaks
7. Check nav, commit (one pattern per commit)

## Agent Integration

- **`AGENTS.md`** (repo root) and **`docs/agent-guide.md`** (on-site) cover the same ground — keep them in sync.
- **`docs/agent-proposal-template.md`** defines the agent output format. If you change it, update `AGENTS.md` too.
- **MCP server** (`mcp-server/server.py`) reads `catalog.json`, which is generated — you rarely need to touch the server.
- **Versioning** lives in the `version` field of `patterns.yml` / `decisions.yml`. Bump it and update `CHANGELOG.md` together.

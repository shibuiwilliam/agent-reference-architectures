# リファレンスアーキテクチャ

!!! abstract "一言"
    個別パターンを**層として重ねた複合構成**の例。「何から始めるか」の出発点として使います。

## パターンの重ね方

パターンを一つずつ理解しても、「実際のシステムではどう組み合わせるの？」が見えないと設計に落とし込みにくいものです。ここでは、典型的なユースケースごとに、複数のパターンを層として重ねた複合構成を紹介します。

各構成には「このパターンを採用する理由」と「省略してよい条件」を併記しています。全てを一度に導入する必要はありません。最小構成から始めて、[駆動変数](../foundations/forces.md) の変化に応じて層を足していくのがよいでしょう。

## 6つの構成

| 構成 | 想定 | 主なフォース |
|------|------|-------------|
| [1. 最小構成（MVP）](01-mvp.md) | 社内ツール・プロトタイプ | `[F2]` 低、`[F8]` 低 |
| [2. 副作用重視構成](02-side-effect-first.md) | 不可逆な操作を含む | `[F1]` 低、`[F2]` 高 |
| [3. 信頼できない入力構成](03-untrusted-input.md) | 不特定ユーザー入力 | `[F5]` 低 |
| [4. 事実性重視構成](04-factuality-first.md) | ハルシネーション不許容 | `[F2]` 高、`[F8]` 高 |
| [5. コスト重視構成](05-cost-first.md) | 大量・低コスト | `[F7]` 高 |
| [6. 継続改善運用構成](06-continuous-improvement.md) | 品質維持・改善 | `[F8]` 高 |

## 選定の5問

どの構成から始めるか迷ったら、以下の5問に答えてください。

1. **失敗したとき何が壊れるか？** → `[F2]` が高ければ[副作用重視構成](02-side-effect-first.md) or [事実性重視構成](04-factuality-first.md)
2. **入力は信頼できるか？** → `[F5]` が低ければ[信頼できない入力構成](03-untrusted-input.md)を重ねます
3. **月間コスト上限は？** → `[F7]` が高ければ[コスト重視構成](05-cost-first.md)を優先します
4. **監査・規制要件はあるか？** → `[F8]` が高ければ[継続改善運用構成](06-continuous-improvement.md)を早期に導入します
5. **まだプロトタイプか？** → はいなら[最小構成](01-mvp.md)から始め、本番化に伴い層を追加します

構成は排他的ではありません。たとえば副作用重視とコスト重視のように、複数の構成を重ね合わせて使うことも珍しくありません。大事なのは、[駆動変数](../foundations/forces.md) に基づいて「なぜこの層が必要か」をきちんと説明できることです。

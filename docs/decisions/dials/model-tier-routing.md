# モデル階層（ルーティング閾値）

!!! abstract "一言"
    リクエストの難易度に応じてLLMモデルを使い分ける際のルーティング閾値を制御します。

## 概要

全リクエストを最高性能モデルに送っていたら月額費用が10倍に膨らんだ。かといって安価なモデルに切り替えたら、複雑な質問への回答品質が目に見えて落ちた——モデルの使い分けは、コストと品質の両立に欠かせません。

このダイヤルは、セマンティックゲートウェイがリクエストを分類し、簡単なものは小型・安価モデルへ、難しいものは大型・高性能モデルへ振り分ける際の分類閾値を決めます。閾値を上げると多くのリクエストが小モデルに流れてコストは下がりますが、難しい問いを小モデルに送って品質が低下するリスクが高まります。

## なぜ調整が必要か

全リクエストを最高性能モデルに送ると月額コストが数倍〜数十倍になります。しかし分類を誤れば、ユーザーは品質の劣化をはっきり感じ取ります。分類器の精度とモデル間の性能差はタスクドメインによって大きく異なるため、万能な閾値は存在しません。

## 値域の両端

### 小さすぎると

分類器が「難しい」と判断する割合が高くなり、大部分のリクエストが高コストモデルに送られます。コスト削減効果がほとんど得られず、ルーティング層のオーバーヘッドだけが残ります。

### 大きすぎると

本来は高性能モデルが必要なリクエストまで小モデルに送られ、回答品質が低下します。不十分な回答に対するリトライや人間エスカレーションが増え、結果的にコストと時間がかさみます。ユーザーの信頼も損なわれます。

## 決め手となるフォース

- `[F7]` コスト感度・スケール — QPSが高くコスト圧力が強いほどルーティングの価値が大きい
- `[F3]` 1リクエストの価値 — 高価値リクエストは安全側（大モデル）に倒す

## 目安（出発点）

- 分類器信頼度0.8以上で「簡単」と判定されたものを小モデルへ
- 分類不能・信頼度不足のリクエストはデフォルトで大モデルへ
- モデル間の品質差が小さいタスク（定型応答・抽出）は積極的に小モデルへ
- 品質差が大きいタスク（推論・創作）は閾値を高めに設定

## 調整の実務

- モデル別・タスク種別の品質スコアを定期的に評価し、ルーティングの妥当性を検証する
- 小モデル送付後の品質低下をユーザーフィードバックや自動評価で検出する
- 新モデルリリース時はルーティング閾値を再校正する
- コスト削減額と品質変化を月次でレポートし、閾値の費用対効果を可視化する

# Budget Cap (Token / Cost)

!!! abstract "TL;DR"
    Set an upper limit on the number of tokens or dollar amount a single request can consume, balancing cost explosion against capability constraints.

## Overview

A developer ran a debug prompt, and the agent entered an infinite loop. By the time it was noticed, a single request had consumed tens of thousands of yen worth of tokens -- operating without a budget cap carries the same risk as a credit card with no spending limit.

This dial determines the upper limit on token count, LLM API cost, and tool call count that an agent can consume processing a single request. For systems that include loops or recursive agent calls, costs become unpredictable without an explicit budget cap. Budgets should be set at multiple granularities: per-request, per-user, and per-time-period.

## Why Adjustment Is Needed

Agents autonomously make tool calls and re-invoke LLMs, so the cost of a single request cannot be determined in advance. Cases where a single request generates costs of thousands of yen due to prompt injection or infinite loops have been reported. Operating without a budget carries the same risk as running a credit card with no spending limit.

## Extremes of the Range

### Too Small

Processing is cut off before producing useful results on complex tasks. Users receive partial results, and re-requesting may actually increase costs. The model's capabilities cannot be fully leveraged.

### Too Large

Cost explosions from bugs or malicious prompts cannot be prevented. Incidents where a single request consumes the entire monthly budget become possible. In multi-agent configurations, each child agent may use close to the limit, causing the total to balloon unexpectedly.

## Determining Forces

- `[F7]` Cost Sensitivity / Scale -- The higher the QPS, the tighter the per-request cap needs to be
- `[F3]` Per-Request Value -- Allocate high budgets to high-value tasks and impose strict limits on low-value tasks

## Guidelines (Starting Point)

- Set cost cap at 10-30% of the value generated by the request
- Low-value, high-frequency: A few thousand tokens total (input + output)
- High-value, low-frequency: Tens of thousands to hundreds of thousands of tokens
- Multi-agent: Parent distributes budget to children, ensuring the total does not exceed the parent's cap

## Practical Adjustment

- Quantify request value (revenue contribution, decision impact) and use it as the basis for cost caps
- Visualize budget consumption distribution daily; review values if the cap-hit rate exceeds 5%
- Implement tiered warnings (70%/90%/100%) and return partial results at 100%
- Set a monthly overall cost cap and distribute to each layer via budget cascading

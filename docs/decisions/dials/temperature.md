# 温度（Temperature）

!!! abstract "一言"
    LLMの出力の確率分布をどれだけ平滑化するかを制御し、再現性と創造性の間を取る。

## 概要

Temperature はLLMのソフトマックス出力の鋭さを調整するパラメータ。0に近いほど最も確率の高いトークンが選ばれやすく出力が決定的になり、高いほど低確率トークンも選ばれやすくなり出力が多様化する。エージェントシステムでは、タスクの性質に応じてステップごとに温度を変えることもある。

## なぜ調整が必要か

定型的な抽出・分類タスクに高い温度を設定すると、不要な変動で精度が落ちる。逆に創造的なタスクや探索的な推論に低い温度を設定すると、局所最適に陥りやすい。エージェントの各ステップ（計画・実行・検証）で最適な温度が異なるため、一律設定では性能を引き出せない。

## 値域の両端

### 小さすぎると

出力が決定的になりすぎ、同じ入力に同じ出力しか返さない。探索的タスクでは局所解に固定され、多様な解決策を提案できない。Best-of-N戦略も候補が同一になり機能しない。

### 大きすぎると

出力のランダム性が高まり、ハルシネーションや文脈から逸脱した回答が増える。構造化出力のフォーマット違反も増加する。再現性が失われ、同じリクエストの結果が毎回異なるためデバッグや評価が困難になる。

## 決め手となるフォース

- `[F6]` タスクの変動性 — 定型タスクは低温度、探索タスクは高温度が基本方針

## 目安（出発点）

- 分類・抽出・構造化出力: 0.0〜0.3
- 要約・翻訳: 0.3〜0.5
- 創作・ブレインストーミング: 0.5〜0.8
- コード生成: 0.0〜0.2（正確性優先）
- エージェントの計画ステップ: 0.3〜0.5（ある程度の探索が有益）

## 調整の実務

- タスク種別ごとに温度を変えるルーティングを実装する（一律設定を避ける）
- 温度変更時は評価セットで品質変化を定量測定する
- Best-of-Nと組み合わせる場合は、温度をやや高めにして候補の多様性を確保する
- バージョン固定と合わせ、温度もデプロイ設定に含めて管理する

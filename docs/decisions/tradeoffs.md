# 相反する仕組みの選定基準

!!! abstract "一言"
    「A か B か」で迷ったとき、駆動変数 `[F#]` で判断する二者択一カタログです。

## 相反とは

「同期と非同期、どちらで処理すべきか」「シングルエージェントかマルチエージェントか」——設計の現場では、こうした二者択一に繰り返し直面します。どちらが正しいかは文脈——つまり [駆動変数](../foundations/forces.md) の値域——によって決まります。

## 方針

二者択一は「片方が常に正しい」という問いではありません。以下の原則で判断します。

1. **デフォルトから始める** — 各択一には「迷ったらこちら」というデフォルトがあります。まずそこから始め、フォースが明確にデフォルトを否定する場合にのみ反対側を選びます
2. **ハイブリッドを検討する** — 多くの択一には、AとBを組み合わせる現実的な中間解があります。二項対立で終わらせず、段階的な適用を考えます
3. **選定理由を記録する** — 「なぜAを選んだか」を設計文書や [ADR](adr-template.md) に残します。フォースが変わったときの再評価の起点になります

## 二者択一の分類と意味

16の二者択一は、設計判断の領域によって4つに分類できます。

## 使い方

1. 設計上の二者択一に直面したら、上表で該当行を探します
2. 「決定変数」列のフォースを自システムで評価します
3. 「デフォルト」を出発点に、各詳細ページの「ハイブリッドアプローチ」が適用可能かを検討します
4. 選定理由を [#32 Agent Trace](../patterns/07-observability/32-agent-trace.md) や設計文書に記録します

相反の選定は一度きりの判断ではありません。フォースの値域が変わったとき——たとえば規制強化やスケール増大などがあった場合——には再評価が必要です。→ [パターンのパラメータ化](parameterization.md)

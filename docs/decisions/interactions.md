# ダイヤル×二者択一の相互作用

!!! abstract "一言"
    ダイヤルと二者択一は独立でなく**連動します**。一方の選択が他方の値域を変えます。

## なぜ相互作用を意識するのか

「非同期を選んだらタイムアウトの自由度が上がったが、今度はチェックポイントの設計が必要になった」——このように、ある決定が別の決定の前提を変えてしまう場面は実務で頻繁に起きます。

[程度（ダイヤル）](tuning-dials.md) と [相反（二者択一）](tradeoffs.md) は別々のカタログに整理されていますが、実際の設計では**連動**します。ある二者択一を解くと関連するダイヤルの値域が変わり、さらに別の二者択一の前提も変わってきます。この連鎖を意識しないと、個別には合理的に見えても全体として矛盾した設計になりかねません。

## 主な相互作用

### 同期↔非同期の選択が変えるもの

| 二者択一の選択 | 影響を受けるダイヤル/二者択一 | 効果 |
|---|---|---|
| **非同期を選ぶ** | タイムアウト上限 | 数分〜数十分に拡大可能 |
| | チェックポイント頻度 | 長時間実行を前提に設計が必要に |
| | プッシュ↔プル | 進捗通知の設計が必須に |
| **同期を選ぶ** | タイムアウト上限 | 5〜10秒に制約 |
| | 自己修正ループ回数 | 1回以下（レイテンシ制約） |

→ [#1 Request-to-Job Gateway](../glossary.md), [#58 Sync Facade](../glossary.md)

### マルチエージェントの選択が変えるもの

| 二者択一の選択 | 影響を受けるダイヤル/二者択一 | 効果 |
|---|---|---|
| **マルチエージェントを選ぶ** | 予算上限 | エージェント数 × 単体予算に膨らむ |
| | トレースサンプリング率 | 観測コストがN倍。層分離が必須に |
| | 露出ツール数 | エージェント毎に絞る必要 |
| | 中央集権↔コレオグラフィ | 新たな二者択一が発生 |

→ [#9 Supervisor & Specialist](../glossary.md), [#55 Deadline & Budget Cascade](../glossary.md)

### インライン検証の選択が変えるもの

| 二者択一の選択 | 影響を受けるダイヤル/二者択一 | 効果 |
|---|---|---|
| **インライン検証を選ぶ** | 自己修正ループ回数 | レイテンシ予算 `[F4]` と競合 |
| | ガードレール厳しさ | 過検知がレイテンシ増に直結 |
| | 同一↔別モデル検証 | 別モデルだとレイテンシ・コスト倍増 |
| **事後検証を選ぶ** | ログ保持期間 | 検証用データの保持が必要 |
| | リトライ回数 | 検証失敗時のリトライ戦略が変わる |

→ [#28 Verifier Agent](../glossary.md), [#29 Guardrail Sidecar](../glossary.md)

### Plan先行の選択が変えるもの

| 二者択一の選択 | 影響を受けるダイヤル/二者択一 | 効果 |
|---|---|---|
| **Plan先行を選ぶ** | HITL頻度 | 計画段階での人間レビューが可能に（実行時HITLを減らせる） |
| | 自律性レベル | 計画承認があれば実行時の自律性を上げられる |
| | ワークフロー↔エージェント | 計画に沿った実行はワークフロー寄りに |
| **ReActを選ぶ** | 自己修正ループ回数 | 各ステップでの修正が必要。回数増 |
| | タイムアウト | 探索的なため予測困難。余裕を持たせる |

→ [#8 Planner-Executor-Reviewer](../glossary.md), [#50 Editable Plan](../glossary.md)

### コスト最適化の選択が連鎖するもの

| 二者択一の選択 | 影響を受けるダイヤル/二者択一 | 効果 |
|---|---|---|
| **モデルルーティングを入れる** | Best-of-N | 小モデルに回した分は N=1 で十分 |
| | キャッシュ類似度閾値 | ルーティングとキャッシュの二重最適化が可能 |
| | 温度 | 小モデル向けは低温度（安定重視） |
| **キャッシュを入れる** | メモリTTL | キャッシュTTLと長期メモリTTLの整合が必要 |

→ [#37 Semantic Gateway](../glossary.md), [#38 Semantic Result Cache](../glossary.md)

## 相互作用の扱い方

1. **二者択一を先に解く**: 二者択一の選択がダイヤルの値域を決めるため、[相反カタログ](tradeoffs.md) を先に引きます
2. **連鎖を辿る**: 上表で選択の影響先を確認し、関連するダイヤルの目安値を再検討します
3. **矛盾を検出する**: 「インライン検証＋低レイテンシ＋多段自己修正」のように、相互に矛盾する要求がないか確認します
4. **トレードオフを記録する**: どの相互作用でどちらを優先したかを [ADR](adr-template.md) に残します

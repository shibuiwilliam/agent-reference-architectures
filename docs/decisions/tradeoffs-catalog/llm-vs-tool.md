# LLM推論で判断 ↔ ツール委譲

!!! abstract "一言"
    正確さが保証できる処理（算術・検索・API呼び出し）はツールに委譲し、LLMは方針決定と自然言語処理に集中させる。

## 概要

「先月の売上合計を教えて」とエージェントに聞いたとき、LLMが頭の中で暗算するのと、データベースにSQLを投げるのでは正確性がまったく違う。どの処理をLLMに任せ、どこをツールに委ねるかは、エージェント設計の根幹に関わる判断である。

この二者択一は、LLMの推論能力で直接処理するか、外部ツール（計算機、検索エンジン、データベース、API）に委譲するかの選択である。LLMの汎用性とツールの正確性のバランスが問われる。

## 選択肢の詳細

### LLM推論で判断

LLMが内部知識と推論能力で直接回答する。ツール呼び出しのオーバーヘッドがなく、レイテンシが低い。自然言語での説明や推論の連鎖、曖昧な判断に強い。ただし算術ミス、知識のカットオフ、ハルシネーションのリスクがある。

### ツール委譲

計算・検索・データ参照を専用ツールに委ねる。算術は正確、検索結果は最新、APIは権威あるデータソースを返す。結果の監査も容易。代償としてツール呼び出しのレイテンシ、ツール障害時のエラーハンドリング、ツール定義の保守が加わる。

## 決定変数

- `[F2]` 失敗コスト — 正確性が求められる処理（金額計算、法的要件の参照等）はツール委譲が必須

## デフォルト（迷ったら）

算術・日付計算・厳密な検索・構造化データの参照はツールに委譲する。LLMは「どのツールを使うか」「結果をどう解釈するか」「ユーザーにどう説明するか」という方針決定と自然言語処理に集中させる。

## ハイブリッドアプローチ

[#15 Inverted Structured Output](../../patterns/03-io-contract/15-inverted-structured-output.md) の考え方で、LLMには「何をすべきか」の判断（中間構造化出力）を生成させ、実際の実行はコードやツールに委ねる。LLMの柔軟な推論とツールの正確な実行を組み合わせる標準的な構成。

# [F9] プロバイダ信頼度（Provider Reliability）

!!! abstract "一言"
    外部LLMプロバイダの可用性やベンダーロックインへの懸念度を測るフォース。信頼度が低いほど、フォールバック・抽象化・マルチプロバイダ戦略が必要になります。

## 概要

深夜にLLMプロバイダが障害を起こし、それに全面依存していた本番サービスが数時間にわたって完全停止した——単一プロバイダへの依存は、プロバイダの障害がそのままシステム全体の障害になることを意味します。

プロバイダ信頼度は、システムが依存する外部LLMプロバイダの可用性・安定性・継続性に対する信頼の度合いを表します。障害・価格改定・API仕様変更・サービス終了といったリスクへの備えが必要な局面では、設計が大きく異なります。

## なぜ重要か

LLMプロバイダは従来のクラウドサービスと比べて障害頻度が高く、レート制限・モデル廃止・API仕様変更も頻繁に発生します。単一プロバイダに強く依存した設計は、プロバイダの障害がそのままシステム全体の停止に直結します。また、特定プロバイダのSDKやプロンプト形式に密結合すると、より優れたモデルや安価なプロバイダへの移行コストが膨大になります。

## 値域の解釈

### 低い場合（信頼度が高い＝リスクが低い）

単一プロバイダで十分と判断できる状況。社内ツール・PoC・トラフィックが少ないシステムで、多少の障害は許容できる場合が該当します。プロバイダのSDKを直接利用し、そのモデル固有の機能（構造化出力、ツール呼び出し形式など）を最大限活用できます。抽象化層のオーバーヘッドを避け、開発速度を優先します。

### 高い場合（信頼度が低い＝リスクが高い）

可用性やベンダーロックインが大きな懸念となる状況。ミッションクリティカルなBtoCサービス、複数地域への展開、長期運用が前提のシステムなどが典型例。プロバイダ障害時のフォールバック経路、モデル差異を吸収する互換レイヤー、プロバイダ非依存のランタイム抽象化が必要になります。複数プロバイダの契約とルーティングロジックの運用コストがかかるが、可用性と交渉力を確保できます。

## 評価の指針

- 使用しているLLMプロバイダの過去半年間の障害頻度と復旧時間はどの程度か
- プロバイダ障害時にシステムが完全に停止するか、縮退運転が可能か
- 現在のプロンプトやツール呼び出し形式がプロバイダ固有のAPIに依存しているか
- プロバイダの価格改定やモデル廃止が発生した場合の移行コストを見積もっているか
- 契約上、特定プロバイダ以外の利用を制限する条項はあるか

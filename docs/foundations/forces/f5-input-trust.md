# [F5] 入力の信頼度（Input Trust）

!!! abstract "一言"
    エージェントへの入力に攻撃や汚染が混入する可能性を測るフォース。信頼度が低いほど、入力の検査・隔離・権限分離が必要になります。

## 概要

社内の管理ツールとして使っていたエージェントを一般ユーザーにも公開したら、翌日にはプロンプトインジェクション攻撃で内部データが漏洩した——入力元が変わるだけで、システムに求められるセキュリティ対策はまったく異なります。

入力の信頼度は、エージェントが受け取るデータがどの程度信頼できるかを表します。社内システムからのAPI呼び出しと、不特定多数のユーザーからの自然言語入力では、リスクの水準が桁違いになります。

## なぜ重要か

LLMベースのエージェントは自然言語を理解するがゆえに、入力に埋め込まれた悪意ある指示（プロンプトインジェクション）に対して構造的に脆弱です。信頼度を考慮しないと、ユーザー入力に含まれる指示がシステムプロンプトを上書きし、権限外の操作を実行させたり、機密データを漏洩させたりします。これは従来のSQLインジェクションと同様、入力境界のサニタイズが不可欠な問題です。

## 値域の解釈

### 低い場合

入力が信頼できる内部ソースに限定される状況。社内バッチシステムからの構造化データ、認証済み管理者からのAPI呼び出し、事前検証済みのデータパイプラインからの入力などが該当します。入力形式が固定されており、悪意ある操作の余地が小さいです。検査を軽くしてスループットを優先できます。

### 高い場合（信頼度が低い＝リスクが高い）

不特定ユーザーからの自然言語入力を受け付ける状況。公開チャットボット、メール処理エージェント、Webフォーム経由のリクエスト、外部ドキュメントのRAG取り込みなどが該当します。プロンプトインジェクション、間接インジェクション（取得文書に埋め込まれた指示）、PII混入の可能性があります。入力の検査・サニタイズ・権限分離が必須になります。

## 評価の指針

- エージェントの入力は認証済みの内部システムからか、不特定ユーザーからか
- 自然言語入力をそのままプロンプトに埋め込んでいるか
- 外部ドキュメントや検索結果をコンテキストに取り込んでいるか（間接インジェクションの経路）
- 入力にPII・機密情報が含まれる可能性はあるか
- エージェントがアクセスできるツール・データの権限レベルはどの程度か

# [F3] 1リクエストの価値（Request Value）

!!! abstract "一言"
    1件のリクエストが売上や意思決定にどれだけ寄与するかを測るフォース。価値が高いほど、1件あたりに投入できる計算資源と検証コストの上限が上がります。

## 概要

検索サジェストの1件に高価な大規模モデルを使えばたちまち赤字ですが、数億円規模のM&A案件のデューデリジェンスなら、モデルを何度呼び出しても十分にペイします。1件のリクエストにどれだけのリソースを投じるべきかは、そのリクエストが生む価値次第です。

1リクエストの価値は、個々のリクエストがビジネスに与えるインパクトの大きさを表します。許容できるコストや品質要求は、この価値に比例して変わります。

## なぜ重要か

このフォースを見落とすと、低価値リクエストに高価なモデルを使って赤字になるか、高価値リクエストに安価なモデルを充てて品質不足に陥ります。リクエスト価値に応じたリソース配分ができなければ、ビジネスとしての持続可能性が損なわれます。

## 値域の解釈

### 低い場合

1件あたりの価値が小さく、大量に処理される状況です。カスタマーサポートの定型応答、商品レコメンド、検索クエリの分類などが典型例です。1件の品質を最大化するより、大量処理のコスト効率とレイテンシが優先されます。キャッシュの活用や軽量モデルへのルーティングが有効です。

### 高い場合

1件が数百万〜数億円の契約や重要な意思決定に紐づく状況です。投資判断の支援、法務契約書のレビュー、医療診断レポート、採用最終候補の評価などが該当します。1件あたりに大型モデルの複数回呼び出しやアンサンブル、人間レビューを投入しても十分にペイするため、品質と正確性をスループットより優先できます。

## 評価の指針

- 1リクエストの成功が直接もたらす売上・コスト削減はいくらか
- リクエスト処理にかけられるLLM API費用の上限は1件あたりいくらか
- 処理品質の向上が顧客満足度やリテンションにどの程度影響するか
- リクエストの量は日次・月次でどの程度か（単価 x 量 の総額で考える）
- 人間が同じタスクを行った場合のコストはいくらか

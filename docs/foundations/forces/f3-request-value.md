# [F3] 1リクエストの価値（Request Value）

!!! abstract "一言"
    1件のリクエストが売上や意思決定にどれだけ寄与するかを測るフォース。価値が高いほど、1件あたりに投入できる計算資源と検証コストの上限が上がる。

## 概要

1リクエストの価値は、個々のリクエストがビジネスに与えるインパクトの大きさを表す。大量の低単価リクエスト（検索サジェスト、FAQ応答）と、1件が大きな契約や経営判断を左右するリクエスト（M&Aデューデリジェンス、法務レビュー）では、許容できるコストと品質要求がまったく異なる。

## なぜ重要か

このフォースを無視すると、低価値リクエストに高価なモデルを使って赤字になるか、高価値リクエストに安価なモデルを充てて品質不足に陥る。リクエスト価値に応じたリソース配分ができなければ、ビジネスとしての持続可能性が損なわれる。

## 値域の解釈

### 低い場合

1件あたりの価値が小さく、大量に処理される状況。カスタマーサポートの定型応答、商品レコメンド、検索クエリの分類などが典型例。1件の品質を最大化するより、大量処理のコスト効率とレイテンシが優先される。キャッシュの活用や軽量モデルへのルーティングが有効になる。

### 高い場合

1件が数百万〜数億円の契約や重要な意思決定に紐づく状況。投資判断の支援、法務契約書のレビュー、医療診断レポート、採用最終候補の評価などが該当する。1件あたりに大型モデルの複数回呼び出しやアンサンブル、人間レビューを投入しても十分にペイする。品質と正確性がスループットに優先する。

## 評価の指針

- 1リクエストの成功が直接もたらす売上・コスト削減はいくらか
- リクエスト処理にかけられるLLM API費用の上限は1件あたりいくらか
- 処理品質の向上が顧客満足度やリテンションにどの程度影響するか
- リクエストの量は日次・月次でどの程度か（単価 x 量 の総額で考える）
- 人間が同じタスクを行った場合のコストはいくらか

# [C8] コストが入力/出力量に比例

!!! abstract "一言"
    トークン課金により、使い方次第でコストが桁違いに変動する——従来の計算リソース管理の前提が通用しない。

## 概要

従来のソフトウェアではインフラコストは主にCPU・メモリ・ストレージで決まり、リクエスト1件あたりのコストはほぼ均一だった。AIエージェントではトークン単位の従量課金が支配的であり、入力の長さ、思考ステップ数、出力の量によってリクエスト単価が数十倍〜数百倍に変動する。RAGで大量の文書をコンテキストに詰め込む、リトライでプロンプトを再送する、self-correctionループを回す——いずれもコストを押し上げる。

## なぜ問題になるか

開発時に月1万円で済んでいたコストが、本番トラフィックで月100万円に跳ね上がる。RAGパイプラインのtop-kを10から50に変更しただけで、入力トークンが5倍になり請求額も5倍になる。ガードレールの自己修正ループが3回走ると、1リクエストのコストが4倍になる。マルチテナントSaaSで1テナントの大量リクエストが共有のコスト上限を食い潰す。予算超過に気づくのが月末の請求書到着時で、手遅れになる。コスト監視の欠如は技術的負債ではなく、事業リスクである。

## 従来ソフトウェアとの比較

| 観点 | 従来のソフトウェア | AIエージェント |
|------|-------------------|---------------|
| リクエスト単価 | ほぼ均一（CPU時間ベース） | 入出力トークン量で桁が変わる |
| コスト予測 | QPS×固定単価で見積もり可能 | タスク難易度・文脈長で大幅に変動 |
| スケーリングコスト | インスタンス数に比例（線形） | トークン消費パターンで非線形に変動 |
| コスト最適化 | キャッシュ、CDN、DB最適化 | プロンプト設計、モデル選択、キャッシュ |

## 影響を受けるフォース

- `[F7]` コスト感度・スケール — 月間コスト上限が厳しいほど、コスト制御パターンの優先度が上がる
- `[F3]` 1リクエストの価値 — リクエスト価値が低い場合、高コストモデルの使用は割に合わない
- `[F4]` レイテンシ予算 — コスト削減のために小型モデルを使うと品質やレイテンシに影響する

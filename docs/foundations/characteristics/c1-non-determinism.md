# [C1] 非決定論的な出力

!!! abstract "一言"
    同じ入力を与えても毎回異なる出力が返る——テスト・再現・比較の前提が根底から崩れる。

## 概要

従来のソフトウェアは同じ入力に対して同じ出力を返す。AIエージェントはそうではない。LLMの確率的サンプリングにより、同一プロンプトでも応答のトーン・構造・内容が変動する。temperature=0 であっても浮動小数点演算の非決定性やバッチ処理の差異により完全な再現は保証されない。

## なぜ問題になるか

本番で最も痛いのは「昨日は通っていたテストが今日は落ちる」という状況である。回帰テストの信頼性が崩壊し、リリース判定が主観に頼るようになる。顧客からの「さっきと違う回答が出た」という問い合わせに対し、ログを見ても入力が同じなのに出力が異なるため原因特定が困難になる。さらに、A/Bテストで差分を評価する際にノイズが大きく、統計的有意性の確保に膨大なサンプル数が必要になる。障害調査で「再現手順」を書いても再現しないという、従来のソフトウェアエンジニアリングでは考えにくい事態が日常化する。

## 従来ソフトウェアとの比較

| 観点 | 従来のソフトウェア | AIエージェント |
|------|-------------------|---------------|
| 同一入力への出力 | 決定論的（同一） | 確率的（毎回変動しうる） |
| 回帰テスト | assert で厳密比較 | 意味的な類似度やスコアで評価 |
| バグ再現 | 入力を再現すれば同じ結果 | 同一入力でも異なる結果になりうる |
| リリース判定 | テスト全通過＝Go | 評価スコアの統計的閾値で判断 |

## 影響を受けるフォース

- `[F2]` 失敗コスト — 高い場合、出力のばらつきが直接的な金銭・法務リスクになる
- `[F8]` 説明責任・規制 — 監査で「なぜこの出力になったか」を説明できない問題が発生する
- `[F3]` 1リクエストの価値 — 高価値なリクエストほど、出力品質のばらつきの影響が大きい

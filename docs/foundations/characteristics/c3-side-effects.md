# [C3] 外部世界への副作用

!!! abstract "一言"
    エージェントはツール呼び出しで外部世界を変更する——メール送信、DB更新、API呼び出しなど、取り消せない操作を自律的に実行します。

## 概要

従来のソフトウェアでは、副作用の発生箇所はコードで明示的に管理されていました。しかしAIエージェントはLLMの判断でツールを選択・実行するため、どの副作用がいつ発生するかをコードレビューだけでは把握できません。しかも副作用の多くは不可逆で、「間違えたので取り消す」が物理的に不可能な場合もあります。

## なぜ問題になるか

たとえば、エージェントがハルシネーションした宛先にメールを送信してしまいます。存在しないチケットIDを参照してDB更新をかけ、データ不整合を起こします。外部APIのレートリミットを超えて連続呼び出しし、アカウントがBANされます。マルチステップの処理で途中のステップが失敗すると、前半の副作用だけが残ってビジネス上の整合性が壊れます（カレンダーには予約が入ったがチケットは未作成、など）。これらは「エージェントが賢くなれば解決する」類の問題ではなく、構造的な防御が必要です。

## 従来ソフトウェアとの比較

| 観点 | 従来のソフトウェア | AIエージェント |
|------|-------------------|---------------|
| 副作用の発生箇所 | コードで静的に確定 | LLMの判断で動的に決定 |
| トランザクション管理 | DB ACID / 2PC | 外部API跨ぎでACIDは使えない |
| 失敗時のロールバック | フレームワークが自動処理 | 補償トランザクションを明示的に設計 |
| テスト | モック差し替えで完結 | ツール呼び出しパターンが非決定的 |

## 影響を受けるフォース

- `[F1]` 可逆性 — 不可逆な操作ほど、事前確認やドライランの重要度が上がる
- `[F2]` 失敗コスト — 金銭・法務・安全に直結する副作用は、承認ゲートが必須になる
- `[F5]` 入力の信頼度 — 信頼できない入力から副作用が発動するとConfused Deputy攻撃になる

## 防波堤となるパターン

- [#4 Agent Saga](../../glossary.md) — 副作用の連鎖に補償トランザクションを組み込み、部分失敗時に巻き戻す
- [#19 Dry-Run First](../../glossary.md) — 実行前に模擬実行で影響範囲を確認し、承認後に本実行する
- [#31 Human Approval Checkpoint](../../glossary.md) — 高リスクな副作用の前に人間の承認を挟む

## 関連する設計判断

- [autonomy-level](../../decisions/dials/autonomy-level.md) — 自律性を上げるほど副作用の自動実行が増え、リスクも上がる
- [hitl-frequency](../../decisions/dials/hitl-frequency.md) — 人間の介入頻度をどこに設定するか
- [checkpoint-frequency](../../decisions/dials/checkpoint-frequency.md) — チェックポイントの間隔が補償トランザクションの粒度を決める

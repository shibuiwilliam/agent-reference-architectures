# [C2] 長時間・可変長の実行

!!! abstract "一言"
    処理時間が数秒から数十分まで振れ、事前に予測できない——HTTPタイムアウトとリソース占有の前提が壊れる。

## 概要

従来のAPIは処理時間がほぼ一定で、タイムアウト値を固定できた。AIエージェントは思考ステップ数が入力に依存し、ツール呼び出しの連鎖で実行時間が桁単位で変動する。「簡単な質問なら2秒、調査タスクなら15分」という状況が同一エンドポイントで起きる。

## なぜ問題になるか

ロードバランサやAPI Gatewayのタイムアウト（典型的には30秒〜60秒）で長時間タスクが途中切断される。クライアントは結果を受け取れず、しかしサーバー側ではエージェントが動き続けてリソースを消費する。マルチテナント環境では、1テナントの長時間タスクがワーカープールを占有し、他テナントのレスポンスタイムが劣化する。オートスケーラーは処理時間の分散が大きいとスケーリング判断を誤り、過剰プロビジョニングかリソース枯渇のどちらかに振れる。ユーザーは進捗が見えないまま待たされ、ブラウザをリロードして二重実行を引き起こす。

## 従来ソフトウェアとの比較

| 観点 | 従来のソフトウェア | AIエージェント |
|------|-------------------|---------------|
| 処理時間 | ほぼ一定（P99も予測可能） | 数秒〜数十分（桁が変わる） |
| タイムアウト設計 | 固定値で十分 | 固定値では短すぎるか長すぎる |
| リソース計画 | QPS×平均処理時間で見積もり | ステップ数が不定でワーカー占有時間が読めない |
| ユーザー体験 | ローディング表示で十分 | 進捗ストリーミングが必要 |

## 影響を受けるフォース

- `[F4]` レイテンシ予算 — ユーザーの待機耐性が低いほど、非同期化や進捗通知の重要度が上がる
- `[F7]` コスト感度・スケール — ワーカー占有時間の変動がインフラコストに直結する
- `[F1]` 可逆性 — 長時間実行の途中失敗時に、中間状態からの復旧が必要になる

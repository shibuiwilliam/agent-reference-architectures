# AIエージェント本番アーキテクチャ・パターン

!!! abstract "基本原理"
    **確率的なコアを、決定論的な殻——契約・検証・予算・権限・観測——で囲む。殻の目盛りは文脈（フォース）で決める。**

## このサイトについて

AIエージェントを本番システムへ組み込むためのアーキテクチャパターン集。**意思決定（フォース・程度・相反）を中心**に、12カテゴリ・59パターンの設計意図・向き不向き・要素技術・調整の勘所を解説する。

パターンは語彙、程度と相反は文法、フォースは文意——本サイトはこの順序で設計判断を組み立てる。

## 対象読者

AIエージェントを本番環境で運用するアーキテクト・エンジニア。プロトタイプから本番への移行で直面する「壊れ方」と、その防波堤としてのパターンを扱う。

## まず「選定の5問」に答える

どこから読むか迷ったら、以下の5問に答えるところから始める。

1. **失敗したとき何が壊れるか？** → `[F2]` が高ければ [副作用重視構成](reference-architectures.md)
2. **入力は信頼できるか？** → `[F5]` が低ければ [信頼できない入力構成](reference-architectures.md)
3. **月間コスト上限は？** → `[F7]` が高ければ [コスト重視構成](reference-architectures.md)
4. **監査・規制要件はあるか？** → `[F8]` が高ければ [継続改善運用構成](reference-architectures.md)
5. **まだプロトタイプか？** → はいなら [最小構成](reference-architectures.md) から始める

→ 5問の詳細は [リファレンスアーキテクチャ](reference-architectures.md) を参照

## 読み方（意思決定から入る）

1. **[意思決定の進め方](decisions/decision-flow.md)** を辿る — フォース評価 → 二者択一 → ダイヤル → 構成合成 → 記録の6ステップ
2. 必要な語彙（パターン）を **[パターン早見表](pattern-index.md)** から引く
3. 具体的な実例は **[通し例](decisions/worked-examples.md)** を参照

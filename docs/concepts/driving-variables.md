# 9つの駆動変数

[程度](../degrees/index.md) の「どこまで」も [相反](../forks/index.md) の「どちら」も、突き詰めるとこの少数の変数で決まります。**設計を始めるときは、まずこの表を対象ユースケースについて埋めてみてください**。frontmatter `driving_variables` にはこの統制語彙（左列の英語キー）のみを使ってください。

| キー | 駆動変数 | 問い | 大きいと寄る方向 |
|---|---|---|---|
| `reversibility` | 可逆性 | 失敗をやり直せるか | 低いほど → 承認・ドライラン・同期確認・厳格検証 |
| `failure_cost` | 失敗コスト | 誤ると金銭/法務/安全がどれだけ痛むか | 高いほど → 多重検証・人間介在・決定論コア |
| `request_value` | 1リクエストの価値 | 売上/意思決定にどれだけ効くか | 高いほど → 高性能モデル・Best-of-N・冗長化 |
| `latency_budget` | レイテンシ予算 | 何秒/何分待てるか | 短いほど → 同期・キャッシュ・軽量モデル・検証簡素化 |
| `input_trust` | 入力の信頼度 | 攻撃/汚染が混ざりうるか | 低いほど → サンドボックス・権限分離・被害限定 |
| `task_variability` | タスクの変動性 | 手順が毎回変わるか定型か | 高いほど → エージェント/自律、低いほど → ワークフロー/決定論 |
| `cost_sensitivity` | コスト感度・スケール | QPS・月間コスト上限はどれだけ厳しいか | 高いほど → ルーター・キャッシュ・縮退・予算上限 |
| `accountability` | 説明責任・規制 | 後で「なぜ」を示す必要があるか | 高いほど → トレース全量・バージョン固定・ポリシーコード化 |
| `provider_trust` | プロバイダ信頼度 | 外部LLMの可用性は安定か | 低いほど → マルチプロバイダ・フォールバック・非同期再実行 |

各 [程度](../degrees/index.md)・[相反](../forks/index.md) では「どの変数が効いたか」を `[駆動変数]` として注記しています。これが提案の根拠になります。

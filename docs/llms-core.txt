# AIエージェント本番アーキテクチャ — 意思決定コア v2.0.0

> 確率的なコアを、決定論的な殻——契約・検証・予算・権限・観測——で囲む。

## 駆動変数（フォース）F1–F9

- **F1 可逆性**: 失敗をやり直せるか
  - 高 → リトライ・再実行が容易。ガードを緩められる
  - 低 → 不可逆操作。補償・承認・Dry-Runが必須
- **F2 失敗コスト**: 金銭/法務/安全の痛み
  - 高 → 多重検証・HITL・Plan先行が必要
  - 低 → 最小構成で十分。事後検証で可
- **F3 1リクエストの価値**: 売上/意思決定への寄与
  - 高 → コストをかけた検証・合議が見合う
  - 低 → 軽量モデル・キャッシュで効率化
- **F4 レイテンシ予算**: ユーザーの待機耐性
  - 高 → 非同期・多段検証を許容できる
  - 低 → 同期・ストリーミング・キャッシュ優先
- **F5 入力の信頼度**: 攻撃/汚染の混入可能性
  - 高 → 社内ユーザー。ガードレール緩め
  - 低 → 不特定入力。境界防御・権限分離が必須
- **F6 タスクの変動性**: 定型↔探索
  - 高 → エージェント・マルチ構成・高温度
  - 低 → ワークフロー・決定論コア・低温度
- **F7 コスト感度・スケール**: QPS・月間コスト上限
  - 高 → ルーティング・キャッシュ・努力配分が必須
  - 低 → 単一モデルで十分
- **F8 説明責任・規制**: 監査・コンプラ要件
  - 高 → 全件トレース・バージョン固定・ポリシーコード化
  - 低 → サンプリング・最低限ログで可
- **F9 プロバイダ信頼度**: 外部LLMの可用性
  - 高 → 単一プロバイダで十分
  - 低 → マルチプロバイダ・フォールバック・抽象化が必要

## 決定規則（IF–THEN候補）

- IF F2=high AND F1=low
  必須: #31, #19, #4
  推奨: #3, #15
  任意: #28, #10
  理由: 不可逆かつ高リスク → #31(承認), #19(Dry-Run), #4(Saga) は必須。#3(骨格) と #15(判断分離) は推奨。#28(検証), #10(合議) は F3 高の場合に追加
- IF F2=high AND F8=high
  必須: #28, #30, #32
  推奨: #33, #10
  任意: #52, #54
  理由: 高リスク＋監査義務 → #28(独立検証), #30(ポリシーコード化), #32(全件トレース) は必須。#33(バージョン固定), #10(合議) は推奨
- IF F5=low
  必須: #13, #42, #44
  推奨: #18, #43, #29
  任意: #20, #41
  理由: 信頼できない入力 → #13(境界), #42(データ検査), #44(権限分離) は必須。#18(最小権限), #43(被害限定), #29(ガードレール) は推奨
- IF F7=high
  必須: #37, #5
  推奨: #38, #39, #56
  任意: #40, #55
  理由: コスト制約 → #37(ルーティング), #5(予算上限) は必須。#38(キャッシュ), #39(プロンプトキャッシュ), #56(努力配分) は推奨
- IF F8=high
  必須: #32, #33
  推奨: #34, #30, #54
  任意: #52, #53
  理由: 監査・規制 → #32(トレース), #33(バージョン固定) は必須。#34(評価CI/CD), #30(ポリシーコード化), #54(二層観測) は推奨
- IF F9=low
  必須: #40
  推奨: #45, #46
  任意: #36
  理由: プロバイダ不安定 → #40(フォールバック) は必須。#45(ランタイム抽象化), #46(互換レイヤー) は推奨
- IF F6=high
  必須: #59
  推奨: #12, #9
  任意: #47
  理由: 探索的タスク → #59(選定メタ) は必須。#12(黒板), #9(統括・専門) は推奨
- IF F6=low
  必須: #3
  推奨: #11
  任意: #14
  理由: 定型タスク → #3(ワークフロー骨格) は必須。#11(決定論コア) は推奨
- IF F3=high
  必須: #10
  推奨: #8, #28
  任意: #37

# 11. LLMに算術や厳密検索をやらせる

!!! abstract "一言"
    LLMに四則演算、日付計算、正規表現マッチ、データベース検索を直接やらせてしまい、計算ミスや検索漏れが頻発するアンチパターン。

## よくある場面

あるECサイトが注文管理エージェントを構築しました。「注文番号 ORD-2024-5678 の合計金額を教えて」という質問に対して、エージェントはデータベースから注文明細を取得し、合計計算をLLMにやらせました。3商品の合計（1,280円 + 3,500円 + 890円）はLLMも「5,670円」と正しく答えました。しかし商品数が10を超えると計算ミスが出始めます。15商品の合計を「43,200円」と回答しましたが、正解は45,180円でした。

別のケースでは、日付計算（「この契約の残日数は？」）でLLMが誤った結果を返し、顧客に間違った情報を伝えてしまいました。さらに、正規表現によるバリデーション（メールアドレス形式のチェック）をLLMに任せたところ、無効な形式を「有効」と判断するケースも出てきました。

## 症状

- 数値計算の結果が不正確です（特に桁数が多い場合や複数ステップの計算）
- 日付・時刻の計算で誤りが発生します（うるう年、タイムゾーン等）
- データベース検索の結果が不完全です（全件取得されない、条件の見落とし）
- 同じ質問に対して異なる計算結果が返ることがあります（再現性がない）
- ユーザーが結果を検証して誤りを指摘するケースが増えます

## 根本原因

LLMは言語モデルであり、「もっともらしい次のトークン」を予測する仕組みです。算術演算は「もっともらしさ」ではなく「正確さ」が求められるタスクなので、LLMの得意分野ではありません。とくに多桁の計算、浮動小数点演算、日付のエッジケースで誤りが起きやすくなります。

データベース検索も同じです。LLMがSQL相当の操作を自然言語の推論で代替しようとすると、条件の見落としや結合ロジックの誤りが生じます。LLMの本来の役割は「何を計算・検索するかを判断すること」であって、「計算・検索そのものを実行すること」ではありません。

## 発見方法

- **計算精度テスト**: エージェントに算術問題を与え、正答率を測定します（特に10項以上の加算、多桁の乗算、日付計算）
- **出力の再現性テスト**: 同じ質問を複数回送信し、同一の結果が返るか確認します
- **ツール呼び出しの確認**: 計算や検索がツール経由で行われているか、LLMの推論のみで行われているかトレースで確認します
- **メトリクス**: `calculation_accuracy_rate`、`search_recall`（検索の再現率）、`tool_call_rate`（ツール委譲率）

## 対策

### ステップ1: 計算・検索タスクを特定しツールを用意する

エージェントが扱うタスクの中で、算術演算、日付計算、データベース検索、正規表現マッチなどの「厳密性が求められる操作」を洗い出し、それぞれに対応するツールを用意します。

### ステップ2: LLMの出力を構造化して、ツールに橋渡しする

LLMには「何を計算するか」「何を検索するか」を構造化された形式で出力させ、実際の計算・検索はツールに委譲します。

### ステップ3: ツール呼び出しを強制する

計算や検索が必要な場面でLLMが自力で回答しようとするのを防ぐため、プロンプトとシステム設計の両面でツール呼び出しを促します。

```python
# ツール定義の例
tools = [
    {
        "name": "calculate",
        "description": "数値計算を実行する。四則演算、集計、統計計算に使用。",
        "parameters": {
            "expression": "計算式（Python式として評価可能な形式）",
        },
    },
    {
        "name": "query_database",
        "description": "データベースを検索する。顧客情報、注文情報等の取得に使用。",
        "parameters": {
            "table": "テーブル名",
            "conditions": "検索条件のリスト",
            "aggregation": "集計方法（省略可）",
        },
    },
    {
        "name": "date_calculate",
        "description": "日付・時刻の計算を行う。差分、加算、フォーマット変換に使用。",
        "parameters": {
            "operation": "計算の種類",
            "dates": "対象の日付リスト",
        },
    },
]
```

## 具体例

### Before（問題のある状態）

```python
# LLMに計算と検索を直接やらせる
response = llm.chat(
    system="あなたは注文管理アシスタントです。",
    messages=[{
        "role": "user",
        "content": f"以下の注文明細の合計金額を計算してください:\n{order_details}"
        # order_details: "商品A: 1,280円, 商品B: 3,500円, ... (15商品)"
    }],
)
# LLMが「合計: 43,200円」と回答（正解: 45,180円）
```

### After（改善後）

```python
# LLMは「何を計算するか」を判断し、計算はツールに委譲
response = llm.chat(
    system="計算が必要な場合は必ず calculate ツールを使用してください。",
    tools=tools,
    messages=[{
        "role": "user",
        "content": f"注文 ORD-2024-5678 の合計金額を教えてください。"
    }],
)

# LLMの出力（ツール呼び出し）:
# {"tool": "query_database", "params": {"table": "order_items",
#   "conditions": [{"order_id": "ORD-2024-5678"}]}}
#
# ツール結果を受けて:
# {"tool": "calculate", "params":
#   {"expression": "1280 + 3500 + 890 + ..."}}
#
# 計算結果: 45180（正確）
```

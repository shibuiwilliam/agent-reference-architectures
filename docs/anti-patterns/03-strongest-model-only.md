# 3. 最強モデル一択

!!! abstract "一言"
    全リクエストに最大・最高性能のモデルを使ってしまい、コストが線形に増大するアンチパターン。

## よくある場面

あるスタートアップが、社内ナレッジベースに対する質問応答エージェントを構築しました。開発時に最新の大規模モデルで検証し、回答品質の高さに満足してそのまま本番投入しました。利用者が増えるにつれ、月額のLLM APIコストが急増しました。内訳を分析すると、リクエストの70%は「営業時間は？」「会議室の予約方法は？」といった定型的な質問で、最小モデルでも十分に回答できるものでした。

チームは「品質を落としたくない」という理由でモデルの変更を避けましたが、コストが予算を超過し、結局利用制限をかけることになりました。全員が高品質な回答を得られるはずが、全員の利用が制限されるという本末転倒な結果になりました。

## 症状

- LLM APIコストがリクエスト数に比例して線形に増大し、スケーリングの壁になります
- 簡単な質問にも数秒のレイテンシがかかり、ユーザーが待たされます
- コスト削減のためにリクエスト数制限やレート制限を導入せざるを得なくなります
- 「もっと安いモデルでよいのでは」という議論が繰り返されますが、切り替え基準がありません

## 根本原因

「最高品質のモデルを使えば間違いない」という単純化が原因です。タスクの難易度は一様ではなく、大半のリクエストは小〜中規模モデルで十分な品質を出せます。しかし、モデル選択をリクエスト単位で動的に行う仕組みを構築するコストを避け、一律に最大モデルを使う方が「楽」だと判断されます。

`[F7]` コスト感度と `[F3]` リクエスト価値のバランスが取れていないことが根本にあります。全リクエストを同一価値として扱っています。

## 発見方法

- **タスク難易度の分布**: リクエストをサンプリングし、小モデルで回答させた場合の品質を評価します。十分な品質が得られるリクエストの割合を算出します
- **コスト対品質の分析**: モデルサイズごとの品質スコアとコストをプロットし、費用対効果の曲線を描きます
- **メトリクス**: `cost_per_request`（モデル別）、`quality_score`（モデル別）、`task_complexity_distribution`

## 対策

### ステップ1: タスクの難易度分類器を導入する

リクエストの難易度を軽量な分類器（ルールベースまたは小モデル）で判定し、適切なモデルにルーティングします。

### ステップ2: 段階的なモデル呼び出しを実装する

まず小モデルで回答を生成し、信頼度が低い場合のみ大モデルにエスカレーションします。

### ステップ3: 品質モニタリングで閾値を調整する

モデルごとの回答品質を継続的に計測し、ルーティング閾値を調整します。

```yaml
# モデルルーティング設定例
routing:
  - condition: "complexity <= simple"
    model: "small-model"
    max_cost: 0.001
  - condition: "complexity <= moderate"
    model: "medium-model"
    max_cost: 0.01
  - condition: "complexity > moderate"
    model: "large-model"
    max_cost: 0.10
```

## 具体例

### Before（問題のある状態）

```python
# 全リクエストを最大モデルで処理
response = llm_client.chat(
    model="gpt-4o",
    messages=[{"role": "user", "content": user_query}],
)
# コスト: 全リクエスト一律 $0.01〜0.05/回
```

### After（改善後）

```python
# 難易度に応じたモデルルーティング
complexity = classify_complexity(user_query)  # 軽量分類器

model_map = {
    "simple": "gpt-4o-mini",    # $0.0001/回
    "moderate": "gpt-4o-mini",  # $0.001/回
    "complex": "gpt-4o",        # $0.01/回
}

response = llm_client.chat(
    model=model_map[complexity],
    messages=[{"role": "user", "content": user_query}],
)
# 平均コスト: $0.002/回（約80%削減）
```

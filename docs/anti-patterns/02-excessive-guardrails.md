# 2. 過剰ガードレール

!!! abstract "一言"
    ガードレールを厳しくしすぎて、正当なリクエストの大半まで遮断してしまい、ユーザー体験を破壊するアンチパターン。

## よくある場面

あるチームがカスタマーサポートエージェントを構築しました。リリース前のセキュリティレビューで「有害な出力を絶対に出してはならない」という要件が追加され、チームはガードレールの閾値を最大レベルに設定しました。本番投入後、「返品したい」という通常の問い合わせが「ネガティブ感情」として検知され、応答がブロックされるケースが頻発しました。医療関連の質問も「危険な内容」としてフィルタリングされました。

ユーザーは繰り返しブロックされることに苛立ち、表現を変えてガードレールを迂回するプロンプトを試し始めました。結果として、ガードレールは正当なユーザーを妨害する一方で、悪意あるユーザーには迂回の手がかりを与えるだけの存在になりました。

## 症状

- 正当なリクエストの遮断率（偽陽性率）が10%を超えます
- ユーザーが同じ意図の質問を言い換えて何度も再送します
- 「ガードレールに引っかからない聞き方」がユーザー間で共有されます
- カスタマーサポートへの「エージェントが使えない」という問い合わせが増加します
- ガードレールの例外リストが肥大化し、保守が困難になります

## 根本原因

セキュリティや安全性に対する恐れから、「厳しくしておけば安全」という判断が下されます。しかし、ガードレールの厳しさは `[F5]` 入力信頼度と `[F2]` 失敗コストのバランスで決めるべきものです。社内ユーザー向けのシステムと不特定多数向けのシステムでは、適切な厳しさが異なります。

また、ガードレールの誤検知率を計測・改善する仕組みがないと、「とにかく厳しく」という方向に倒れがちです。偽陽性のコスト（ユーザー離脱、業務効率低下）が定量化されていないことも一因です。

## 発見方法

- **偽陽性率の計測**: ブロックされたリクエストをサンプリングして人手でレビューし、正当なリクエストの割合を算出します
- **ユーザー行動分析**: 同一ユーザーが短時間に類似リクエストを繰り返していないか確認します
- **ガードレール発火率**: 全リクエストに占めるガードレール発火の割合が5%を超えていないか確認します
- **メトリクス**: `guardrail_block_rate`、`false_positive_rate`、`user_retry_rate`

## 対策

### ステップ1: 段階的なガードレールを設計する

「即座にブロック」「警告付きで通過」「ログのみ」の3段階を設け、リスクレベルに応じて振り分けます。最初から全てをブロックしません。

### ステップ2: 偽陽性率を計測・改善するサイクルを回す

ブロックされたリクエストを定期的にサンプリングし、偽陽性率を計測します。閾値を調整し、偽陽性率が目標値（例: 1%以下）に収まるまで反復します。

### ステップ3: ガードレールをコード化しテスト可能にする

ルールをコードとして管理し、テストケース（正当なリクエスト集合と有害なリクエスト集合）で回帰テストを行います。

```yaml
# ガードレール設定例
guardrails:
  - name: toxicity_filter
    threshold: 0.85        # 高閾値 = 明確に有害なもののみブロック
    action: block
  - name: sentiment_check
    threshold: 0.95        # 極めて高閾値 = ほぼブロックしない
    action: warn_and_log
  - name: pii_detector
    threshold: 0.70
    action: redact          # ブロックではなくマスク処理
```

## 具体例

### Before（問題のある状態）

```python
# 全ルールを一律の厳しい閾値で適用
guardrail_result = check_all_guardrails(
    input=user_message,
    threshold=0.5,  # 低閾値 = 広範囲にブロック
    action="block",
)
if guardrail_result.blocked:
    return "申し訳ありません。このリクエストには対応できません。"
```

### After（改善後）

```python
# リスクレベルに応じた段階的ガードレール
guardrail_result = check_guardrails(
    input=user_message,
    rules=load_rules("guardrails.yaml"),
)

if guardrail_result.hard_block:
    return "安全上の理由でお答えできません。"
elif guardrail_result.soft_block:
    log_for_review(user_message, guardrail_result)
    return agent.run(user_message, with_disclaimer=True)
else:
    return agent.run(user_message)
```

# #18 Least-Privilege Tool Binding｜最小権限バインディング

!!! abstract "一言"
    エージェントに渡すツール群を**セッション・タスク・ユーザー単位で最小限に束縛**し、不要な権限を持たせない。

## 概要

エージェントにすべてのツールを常時公開すると、プロンプトインジェクションや誤判断で意図しないツールが呼ばれるリスクが増大する。本パターンでは、セッション開始時にタスク種別・ユーザー権限・コンテキストに基づいて利用可能なツールセットを動的に絞り込む。エージェントからは「存在しないツールは呼べない」ため、攻撃面と事故の半径が構造的に縮小する。

## 設計

セッション開始時に Binder がユーザーのロール、タスク種別、リスクレベルを評価し、ツールカタログから該当セッションで許可するツールだけを抽出してエージェントに注入する。セッション途中でのツール追加は再評価を経る。

権限の粒度はツール単位だけでなく、ツール内のパラメータ制約（例: `delete` は禁止、`read` のみ許可）まで含められる。

## 解決する課題

「全ツール公開」はエージェントの選択肢爆発（ツール数が増えると選択精度が下がる）と、被害半径の拡大を同時に招く。`[F5]` インジェクション攻撃で高権限ツールが呼ばれるリスクを構造的に排除し、`[F2]` 誤操作時の被害を限定する。

## 向き / 不向き

- **向き**: ツール数が多い（10以上）システム。マルチテナント環境。権限レベルが異なるユーザーが同一エージェントを共用する場合。
- **不向き**: ツールが2〜3個で全ユーザーが同権限のシンプルな構成。動的なツール発見が必要な探索的タスク。

## 要素技術

- MCP の `tools/list` フィルタリング
- ツールカタログ + RBAC / ABAC エンジン
- セッションスコープのツールセット注入（LLM の system prompt / tools パラメータ制御）
- OPA / Cedar によるポリシー評価

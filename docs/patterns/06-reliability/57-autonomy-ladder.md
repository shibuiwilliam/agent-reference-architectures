# #57 Autonomy Ladder｜自律性のはしご

!!! abstract "一言"
    エージェントの自律レベルを**段階的に定義**し、実績と信頼に応じて昇格・降格させる。

## 概要

エージェントに最初から完全な自律権を与えるのはリスクが高く、逆にすべてを人間承認にすると自動化の意味がない。Autonomy Ladder は自律レベルを明示的な段階（例: L0 提案のみ → L1 承認後実行 → L2 事後通知付き自動実行 → L3 完全自動）として定義し、エージェントの実績・成功率・失敗履歴に基づいてレベルを上下させる仕組みを導入する。

## 設計

| レベル | 動作 | 人間の関与 |
|--------|------|------------|
| L0 | 提案を提示するのみ | 人間がすべて実行 |
| L1 | 実行計画を提示し承認後に実行 | 事前承認 |
| L2 | 自動実行し事後に通知 | 事後レビュー |
| L3 | 完全自動。異常時のみ通知 | 例外時のみ |

昇格条件は定量的に定める（例: 直近100タスクの成功率95%以上で L1→L2）。降格条件も同様に定め（重大インシデント発生で即時降格）、一方通行にしない。レベルはタスク種別ごとに独立して管理する。例えば「メール下書きはL2だが、送金はL1」のように粒度を分ける。

## 解決する課題

自律性の付与を all-or-nothing で扱うと、エージェントの能力が証明されるまでスケールしない `[F1]` か、証明なしに権限を与えて事故を招く `[F2]`。ラダー方式は (1) 導入初期のリスクを限定し、(2) 信頼の蓄積を定量的に管理し、(3) 問題発生時に即座に権限を絞れる。組織への導入時の「怖いから全部手動」を段階的に解消する。

## 向き / 不向き

- **向き**: 段階的に自動化範囲を広げたい業務プロセス、リスクレベルがタスクごとに異なるマルチタスクエージェント。
- **不向き**: 全タスクが同一リスクで常に人間監視が必要な領域（常にL1固定で十分）、タスク件数が少なく統計的な信頼度評価ができない場合。

## 要素技術

- レベル管理: 設定DB / Feature Flag（LaunchDarkly等）
- 実績追跡: 成功/失敗/インシデントのカウンタ、スコアリングモデル
- 昇降格ロジック: ルールベース（閾値）、または統計的信頼区間
- 通知: レベル変更時のアラート、ダッシュボード表示

## 調整（程度）

- **昇格の閾値** — 低すぎると未熟なまま自律化、高すぎると永遠にL0のまま / 決め手 `[F1][F2]` / タスクの不可逆性に応じて閾値を変える。→ [程度ダイヤル](../../decisions/tuning-dials.md)

## 選定（相反）

- **自律性 ↔ 人間制御** — エージェントの自律レベルをどこに設定するかはこのパターンの中核的な判断 `[F1][F2]`。→ [相反の選定基準](../../decisions/tradeoffs.md)

# #57 Autonomy Ladder｜自律性のはしご

!!! abstract "一言"
    エージェントの自律レベルを**段階的に定義**し、実績と信頼に応じて昇格・降格させる。

## 概要

新しく配属された社員にいきなり全権限を渡すことはしない。まずは提案を出してもらい、上長が承認し、実績を見ながら徐々に裁量を広げていく。エージェントの自律性も同じ発想で管理できる。最初から完全な自律権を与えるのはリスクが高いが、すべてを人間承認にしてしまうと自動化の意味がなくなってしまう。Autonomy Ladder は自律レベルを明示的な段階（たとえば L0 提案のみ → L1 承認後実行 → L2 事後通知付き自動実行 → L3 完全自動）として定義し、エージェントの実績・成功率・失敗履歴に基づいてレベルを上下させる仕組みを導入するパターンである。

!!! info "意思決定上の位置づけ"
    - **必要にするフォース**: `[F1]` 可逆性・`[F2]` 失敗コスト
    - **関与する決定**: [程度（ダイヤル）](../../decisions/tuning-dials.md) の 自律性レベル
    - **意思決定の進め方**: [意思決定の進め方](../../decisions/decision-flow.md)

## 設計

| レベル | 動作 | 人間の関与 |
|--------|------|------------|
| L0 | 提案を提示するのみ | 人間がすべて実行 |
| L1 | 実行計画を提示し承認後に実行 | 事前承認 |
| L2 | 自動実行し事後に通知 | 事後レビュー |
| L3 | 完全自動。異常時のみ通知 | 例外時のみ |

昇格条件は定量的に定める（たとえば、直近100タスクの成功率が95%以上で L1→L2 に昇格するなど）。降格条件も同様に定め（重大インシデント発生で即時降格など）、一方通行にしないことが重要である。レベルはタスク種別ごとに独立して管理する。たとえば「メール下書きはL2だが、送金はL1」のように粒度を分けることができる。

## 解決する課題

自律性の付与を all-or-nothing で扱うと、エージェントの能力が証明されるまでスケールできない `[F1]` か、証明なしに権限を与えて事故につながる `[F2]` かのどちらかになりがちである。ラダー方式であれば、(1) 導入初期のリスクを限定し、(2) 信頼の蓄積を定量的に管理し、(3) 問題発生時に即座に権限を絞ることができる。組織への導入時にありがちな「怖いから全部手動」という状態を、段階的に解消していける。

## 向き / 不向き

- **向き**: 段階的に自動化範囲を広げたい業務プロセスや、リスクレベルがタスクごとに異なるマルチタスクエージェントに適している。
- **不向き**: 全タスクが同一リスクで常に人間監視が必要な領域には不要である（常にL1固定で十分）。また、タスク件数が少なく統計的な信頼度評価ができない場合にも効果が薄い。

## 要素技術

- レベル管理: 設定DB / Feature Flag（LaunchDarkly等）
- 実績追跡: 成功/失敗/インシデントのカウンタ、スコアリングモデル
- 昇降格ロジック: ルールベース（閾値）、または統計的信頼区間
- 通知: レベル変更時のアラート、ダッシュボード表示

## 調整（程度）

- **昇格の閾値** — 低すぎると未熟なまま自律化、高すぎると永遠にL0のまま / 決め手 `[F1][F2]` / タスクの不可逆性に応じて閾値を変える。→ [程度ダイヤル](../../decisions/tuning-dials.md)

## 選定（相反）

- **自律性 ↔ 人間制御** — エージェントの自律レベルをどこに設定するかはこのパターンの中核的な判断 `[F1][F2]`。→ [相反の選定基準](../../decisions/tradeoffs.md)

# #5 Time-Budgeted Agent Loop｜予算付きループ

!!! abstract "一言"
    エージェントの推論ループに**時間・ステップ回数・トークン消費・金額**の予算上限を設定し、超過前に強制終了または縮退させる。

## 概要

エージェントの ReAct / Plan-Execute ループは本質的に終了条件が不確定であり、無限ループや想定外の深掘りが起こりうる。このパターンでは、ループ開始時に予算（wall-clock時間、最大ステップ数、累積トークン数、API呼び出し回数、金額上限）を注入し、各イテレーションで残予算をチェックする。超過時は「現時点の最善回答を返す」「要約して終了」「人間にエスカレーション」のいずれかに縮退する。

## 設計

```mermaid
flowchart TD
    Start[ループ開始 + 予算注入] --> Check{残予算 > 0?}
    Check -->|Yes| Step[LLM推論 + ツール実行]
    Step -->|予算消費を記録| Check
    Check -->|No| Degrade[縮退: 最善結果を返却]
```

予算は構造体として保持し、LLM呼び出し・ツール実行ごとに消費量を加算する。残予算はプロンプトにも含め、LLM自身にも「あと何ステップか」を認識させる。

## 解決する課題

エージェントの暴走は `[F7]` コスト爆発と `[F3]` 低価値リクエストへの過剰投資を引き起こす。また下流サービスのレート制限を食い潰したり、他リクエストのリソースを奪ったりする。予算を明示的に設けることで、コストとレイテンシの上界を保証する。

## 向き / 不向き

- **向き**: ユーザー向けサービスでコスト・レイテンシの上限を保証したい場合。マルチテナント環境でテナント間の公平性を担保したい場合。
- **不向き**: バッチ処理で「かかるだけかかってよい」タスク。ただしその場合でも金額上限だけは設けることを推奨する。

## 要素技術

- 予算管理: フレームワークのコールバック / ミドルウェアで各ステップに差し込み
- 計測: LLM APIレスポンスの `usage` フィールドからトークン数を取得、ツール呼び出し回数をカウント
- 通知: 予算の80%消費時に警告ログを出力し、[#7 Streaming Progress](07-streaming-progress.md) で残予算をユーザーに表示
- カスケード: 子エージェントへの予算配分は [#55 Deadline & Budget Cascade](55-deadline-budget-cascade.md) を参照

## 調整（程度）

- **予算サイズ** — 小さすぎると有用な回答に到達できない ⇔ 大きすぎるとコスト制御の意味がない / 決め手 `[F3]``[F7]` / 目安: リクエスト当たりの期待収益の10〜30%をコスト上限に。→ [程度ダイヤル](../../decisions/tuning-dials.md)

# #50 Editable Plan｜編集可能プラン

!!! abstract "一言"
    エージェントが生成した実行計画を、実行前に人間が確認・編集・並べ替え・削除できるようにする。

## 概要

エージェントに「競合分析レポートを作って」と依頼したら、見当違いの情報源を調べ始め、30分後に出来上がったレポートが的外れだった――実行前に計画を確認できていれば防げた失敗である。

エージェントにタスクを依頼すると、内部的に実行計画（ステップの列）を生成する。この計画を「ブラックボックスのまま即実行」するのではなく、ユーザーに提示して編集の機会を与える。ステップの追加・削除・並べ替え・パラメータ修正を受け付けたうえで実行に移ることで、エージェントの判断ミスを実行前に修正できる。探索的タスクほど計画の精度が低くなりやすいため `[F6]`、人間による修正が大きな価値を持つ。

!!! info "意思決定上の位置づけ"
    - **必要にするフォース**: `[F6]` タスクの変動性
    - **関与する決定**: [相反](../../decisions/tradeoffs.md) の Plan↔ReAct

## 設計

1. ユーザーがタスクを指示
2. エージェントが計画を生成し、構造化データ（JSON / YAML）としてUIに返す
3. UIが計画をステップ一覧として表示。各ステップは編集・削除・並べ替え可能
4. ユーザーが「実行」を押すと、編集後の計画でエージェントが動作
5. 実行中に計画変更が必要になった場合、エージェントが再計画を提案し再度編集を受け付ける

計画の構造は [#14 Structured Output Contract](../03-io-contract/14-structured-output-contract.md) でスキーマ化し、UIとエージェント間の契約とする。

## 解決する課題

エージェントの計画能力は万能ではなく、特に未知の領域や複雑なタスクでは不適切なステップを含むことがある `[F6]`。実行後に誤りに気づくと、副作用の巻き戻しコストが発生する。実行前に人間が計画を精査・修正できれば、こうした試行錯誤のコストを大幅に削減できる。

## 向き / 不向き

- **向き**: 複数ステップのタスクで、ステップの順序や内容が結果に大きく影響するケース。副作用を伴い、やり直しコストが高いワークフロー。
- **不向き**: 計画が1〜2ステップで自明なタスク。リアルタイム性が求められ、人間の編集待ちが許容されないケース。完全自律が求められるバッチ処理。

## 要素技術

- 計画フォーマット: JSON / YAML でステップを構造化（タイトル、説明、ツール、パラメータ）
- UI: ドラッグ&ドロップ対応のステップエディタ、インライン編集
- 再計画: エージェントが実行中に計画変更を提案するフィードバックループ
